1  Neural Networks and Optimization

1.1 Overview

This chapter establishes the mathematical and architectural foundations of modern deep learning. Understanding these fundamentals is essential for research scientist interviews, as they underpin all contemporary models—from vision transformers to large language models. We cover the core building blocks (layers, activations, normalization), the learning algorithms (backpropagation, optimization), and the principles that enable generalization.

Key Interview Topics: Network architecture design, gradient flow and vanishing gradients, optimization algorithm selection, regularization strategies, batch normalization mechanics.

1.2 Supervised Learning Framework

In supervised learning, we are given a dataset \(\mathcal{D} = \{(\mathbf{x}_1, y_1), \ldots, (\mathbf{x}_m, y_m)\}\), where: - \(\mathbf{x}_i \in \mathbb{R}^d\) are input feature vectors - \(y_i \in \mathcal{Y}\) are corresponding targets (labels)

Each pair \((\mathbf{x}_i, y_i)\) is assumed to be sampled i.i.d. from some unknown joint distribution \(p(\mathbf{x}, y)\), where \(\mathbf{x} \sim p(\mathbf{x})\) and \(y \sim p(y|\mathbf{x})\).

Learning Objective: Find a function \(f_\theta: \mathbb{R}^d \rightarrow \mathcal{Y}\) that approximates the conditional distribution \(p(y|\mathbf{x})\), or equivalently, minimizes the expected prediction error.

Neural networks represent \(f_\theta\) as a composition of simple linear and nonlinear transformations, whose parameters \(\theta\) are optimized to minimize the discrepancy between predictions \(\hat{y}_i = f_\theta(\mathbf{x}_i)\) and observed targets \(y_i\).

Why This Matters: Understanding the probabilistic view of supervised learning explains why we use cross-entropy for classification (log-likelihood) and MSE for regression (Gaussian likelihood assumption). In interviews, you may be asked to justify loss function choices or discuss when supervised learning assumptions break down.

1.3 Neural Network Architecture

1.3.1 Linear Layers

Definition: A linear (or fully-connected/dense) layer performs an affine transformation:

\[\mathbf{z} = \mathbf{W}^\top \mathbf{x} + \mathbf{b}\]

where: - \(\mathbf{x} \in \mathbb{R}^{d_{\text{in}}}\) is the input - \(\mathbf{W} \in \mathbb{R}^{d_{\text{in}} \times d_{\text{out}}}\) is the weight matrix
- \(\mathbf{b} \in \mathbb{R}^{d_{\text{out}}}\) is the bias vector - \(\mathbf{z} \in \mathbb{R}^{d_{\text{out}}}\) is the pre-activation output

Parameter Count: \(d_{\text{in}} \times d_{\text{out}} + d_{\text{out}}\)

Initialization Strategy:

  • Weights \(\mathbf{W}\): Sample from \(\mathcal{N}(0, \sigma^2)\) where \(\sigma\) depends on the initialization scheme:
    • Xavier/Glorot: \(\sigma^2 = \frac{2}{d_{\text{in}} + d_{\text{out}}}\) (for sigmoid/tanh)
    • He/Kaiming: \(\sigma^2 = \frac{2}{d_{\text{in}}}\) (for ReLU)
  • Bias \(\mathbf{b}\): Initialize to zero vector

Why Random Initialization? Without randomness, all neurons in a layer would compute identical gradients during backpropagation and remain symmetric. Proper initialization also prevents vanishing/exploding activations in deep networks by keeping variance stable across layers.

Interview Insight: Be prepared to explain why He initialization uses \(2/d_{\text{in}}\) instead of Xavier’s \(2/(d_{\text{in}} + d_{\text{out}})\). The answer relates to ReLU killing half the activations (setting negatives to zero), which requires compensating with larger variance.

1.3.2 Activation Functions

Activation functions introduce non-linearity, enabling networks to learn complex decision boundaries. Without them, stacking linear layers would remain equivalent to a single linear transformation.

Common Activation Functions:

Activation Formula Derivative Range
Sigmoid \(\sigma(z) = \frac{1}{1+e^{-z}}\) \(\sigma(z)(1-\sigma(z))\) \((0, 1)\)
Tanh \(\tanh(z) = \frac{e^z - e^{-z}}{e^z + e^{-z}}\) \(1 - \tanh^2(z)\) \((-1, 1)\)
ReLU \(\text{ReLU}(z) = \max(0, z)\) \(\mathbb{1}_{z > 0}\) \([0, \infty)\)
Leaky ReLU \(\text{LeakyReLU}(z) = \max(0.01z, z)\) \(\begin{cases} 1 & z > 0 \\ 0.01 & z \leq 0 \end{cases}\) \((-\infty, \infty)\)
GELU \(\text{GELU}(z) = z \cdot \Phi(z)\) (complex, approximated) \((-0.17z, \infty)\)

where \(\Phi(z)\) is the cumulative distribution function of standard normal distribution.

Properties and Trade-offs:

  1. Sigmoid/Tanh:

    • Saturate for large \(|z|\) → gradients vanish → slow learning in deep networks
    • Still used in gates (LSTMs, GRUs) where squashing to \((0,1)\) is desirable

  2. ReLU:

    • Computationally efficient (simple thresholding)
    • Sparse activation (many zeros)
    • Dying ReLU problem: Neurons with large negative bias may never activate

  3. Leaky ReLU:

    • Prevents dying ReLU by allowing small negative gradient
    • Hyperparameter \(\alpha = 0.01\) often works well

  4. GELU (Gaussian Error Linear Unit):

    • Smooth approximation to ReLU
    • Used in Transformers (BERT, GPT)
    • Allows small negative values to pass through

Interview Question: “Why do modern architectures prefer ReLU over sigmoid?” Answer: ReLU doesn’t saturate for positive values (gradient = 1), enabling faster training and mitigating vanishing gradients. It also introduces sparsity, which may help with feature selection.

1.3.3 Dropout Regularization

Motivation: Neural networks with large capacity tend to overfit training data. Dropout provides an efficient regularization mechanism by preventing co-adaptation of neurons.

Training Phase: For each mini-batch, randomly set activation outputs to zero with probability \(1 - p_{\text{keep}}\):

\[\mathbf{a}_{\text{dropout}} = \mathbf{m} \odot \mathbf{a} \cdot \frac{1}{p_{\text{keep}}}\]

where:

  • \(\mathbf{m} \sim \text{Bernoulli}(p_{\text{keep}})\) is a binary mask
  • \(\odot\) denotes element-wise multiplication
  • The scaling factor \(1/p_{\text{keep}}\) maintains expected activation magnitude

Inference Phase: Use all neurons without dropout (\(\mathbf{a}_{\text{test}} = \mathbf{a}\)). The training-time scaling ensures test-time expectations match.

Intuition: Dropout can be viewed as:

  1. Implicit Ensemble: Training an exponential number of sub-networks that share parameters
  2. Regularization: Prevents complex co-adaptations by forcing neurons to be robust individually

Typical Values: \(p_{\text{keep}} \in [0.5, 0.8]\) for hidden layers; often \(p_{\text{keep}} = 1.0\) (no dropout) for input/output layers.

Interview Note: Modern architectures (especially Transformers) often use dropout sparingly or replace it with other regularization (weight decay, layer normalization). Be ready to discuss this trend.

1.3.4 Normalization Techniques

1.3.4.1 Batch Normalization

Motivation: During training, the distribution of inputs to each layer changes as parameters update (internal covariate shift). This forces layers to continuously adapt, slowing convergence. Batch Normalization stabilizes these distributions.

Algorithm (applied per mini-batch):

Given a mini-batch \(\mathcal{B} = \{\mathbf{z}^{(1)}, \ldots, \mathbf{z}^{(B)}\}\) where \(\mathbf{z}^{(i)} \in \mathbb{R}^d\):

  1. Compute statistics per dimension \(j = 1, \ldots, d\): \[\mu_j = \frac{1}{B} \sum_{i=1}^B z_j^{(i)}\] \[\sigma_j^2 = \frac{1}{B} \sum_{i=1}^B (z_j^{(i)} - \mu_j)^2\]

  2. Normalize: \[\hat{z}_j^{(i)} = \frac{z_j^{(i)} - \mu_j}{\sqrt{\sigma_j^2 + \epsilon}}\]

    where \(\epsilon \approx 10^{-5}\) prevents division by zero

  3. Scale and shift (learnable parameters): \[y_j^{(i)} = \gamma_j \hat{z}_j^{(i)} + \beta_j\]

Parameters: Each dimension has learnable \(\gamma_j\) (scale) and \(\beta_j\) (shift). This allows the network to undo normalization if beneficial.

Inference: Use running averages of \(\mu_j\) and \(\sigma_j^2\) computed during training: \[\mu_{\text{running}} \leftarrow \alpha \mu_{\text{running}} + (1-\alpha) \mu_{\text{batch}}\] \[\sigma^2_{\text{running}} \leftarrow \alpha \sigma^2_{\text{running}} + (1-\alpha) \sigma^2_{\text{batch}}\]

where \(\alpha \approx 0.9\) is the momentum parameter.

Placement: Typically applied before activation functions (though after activation is also used): \[\mathbf{y} = \text{Activation}(\text{BatchNorm}(\mathbf{W}^\top \mathbf{x} + \mathbf{b}))\]

Benefits:

  1. Enables higher learning rates (gradients don’t explode/vanish as easily)
  2. Acts as regularizer (each sample sees different normalizations due to batch sampling)
  3. Reduces sensitivity to initialization

Numpy Implementation (forward pass only):

def batch_norm_forward(x, gamma, beta, eps=1e-5):
    """
    x: (N, D) input
    gamma, beta: (D,) scale and shift parameters
    """
    # Compute statistics
    mu = np.mean(x, axis=0)  # (D,)
    var = np.var(x, axis=0)  # (D,)
    
    # Normalize
    x_normalized = (x - mu) / np.sqrt(var + eps)
    
    # Scale and shift
    out = gamma * x_normalized + beta
    
    # Cache for backward pass
    cache = (x, x_normalized, mu, var, gamma, beta, eps)
    return out, cache

Interview Deep-Dive: Be ready to explain:

  • Why running statistics are needed at test time (batch size = 1)
  • Why BatchNorm breaks in small batches or sequence models (→ LayerNorm)
  • The controversy around “internal covariate shift” vs. just smoothing loss landscape

1.3.4.2 Normalization Variants for Images

For convolutional networks with spatial dimensions, different normalization strategies are used:

Method Normalization Axes Use Case
Batch Norm \((N, H, W)\) per channel Standard CNNs with moderate batch size
Layer Norm \((C, H, W)\) per sample Small batches, sequence models
Instance Norm \((H, W)\) per channel per sample Style transfer, GANs
Group Norm Groups of channels \((G, H, W)\) Very small batches

Tensor Notation: For input \(\mathbf{X} \in \mathbb{R}^{N \times C \times H \times W}\):

  • \(N\) = batch size
  • \(C\) = channels
  • \(H, W\) = spatial dimensions

BatchNorm2D: Normalize across \((N, H, W)\) for each channel \(c\): \[\hat{x}_{n,c,h,w} = \frac{x_{n,c,h,w} - \mu_c}{\sqrt{\sigma_c^2 + \epsilon}}\] where \(\mu_c, \sigma_c^2\) are computed over all \(N \times H \times W\) spatial positions.

LayerNorm: Normalize across \((C, H, W)\) for each sample \(n\): \[\hat{x}_{n,c,h,w} = \frac{x_{n,c,h,w} - \mu_n}{\sqrt{\sigma_n^2 + \epsilon}}\]

Why LayerNorm for Transformers? Sequence lengths vary, making batch statistics unstable. LayerNorm computes statistics per sample, avoiding this issue. It’s now standard in Transformers (BERT, GPT, ViT).

1.4 Loss Functions

1.4.1 Binary Classification

Logistic Regression Model: \[\hat{y} = \sigma(\mathbf{w}^\top \mathbf{x} + b), \quad \sigma(z) = \frac{1}{1 + e^{-z}}\]

Binary Cross-Entropy (BCE) Loss: \[\mathcal{L}(\theta) = -\frac{1}{m} \sum_{i=1}^m \left[ y_i \log \hat{y}_i + (1 - y_i) \log(1 - \hat{y}_i) \right]\]

where \(y_i \in \{0, 1\}\) is the ground truth label.

Probabilistic Interpretation:

  • Minimizing BCE is equivalent to maximum likelihood estimation (MLE) under Bernoulli distribution
  • \(\hat{y}_i\) represents \(P(y=1 | \mathbf{x}_i; \theta)\)

Gradient (for single example): \[\frac{\partial \mathcal{L}}{\partial \mathbf{w}} = (\hat{y} - y) \mathbf{x}\]

This clean gradient is why we use log loss (the exponentials cancel nicely).

1.4.2 Multi-Class Classification

Softmax Function: For logits \(\mathbf{z} = [z_1, \ldots, z_K]^\top \in \mathbb{R}^K\), the softmax produces a probability distribution:

\[\text{softmax}(\mathbf{z})_k = \frac{e^{z_k}}{\sum_{j=1}^K e^{z_j}}\]

Properties:

  • \(\sum_{k=1}^K \text{softmax}(\mathbf{z})_k = 1\) (valid probability distribution)
  • Translation invariant: \(\text{softmax}(\mathbf{z} + c) = \text{softmax}(\mathbf{z})\) for constant \(c\)
  • Smooth approximation to argmax (approaches one-hot as temperature \(\rightarrow 0\))

Temperature Scaling: \[\text{softmax}(\mathbf{z}/T)_k = \frac{e^{z_k/T}}{\sum_{j=1}^K e^{z_j/T}}\]

  • \(T > 1\): Softer distribution (less confident)
  • \(T < 1\): Sharper distribution (more confident)

Categorical Cross-Entropy (CCE) Loss: \[\mathcal{L}(\theta) = -\frac{1}{m} \sum_{i=1}^m \sum_{k=1}^K y_{i,k} \log \hat{y}_{i,k}\]

where:

  • \(\mathbf{y}_i \in \{0,1\}^K\) is the one-hot encoded label
  • \(\hat{\mathbf{y}}_i = \text{softmax}(\mathbf{z}_i)\) is the predicted probability

Simplified Form (since only one \(y_{i,k} = 1\)): \[\mathcal{L}(\theta) = -\frac{1}{m} \sum_{i=1}^m \log \hat{y}_{i, c_i}\]

where \(c_i\) is the true class index for example \(i\).

Numerical Stability: Compute log-softmax directly to avoid overflow: \[\log \text{softmax}(\mathbf{z})_k = z_k - \log \sum_{j=1}^K e^{z_j}\]

Interview Question: “Why not use MSE for classification?” Answer: MSE assumes Gaussian likelihood, inappropriate for discrete labels. Cross-entropy corresponds to the correct likelihood (categorical distribution) and provides better gradients for probability outputs.

1.4.3 Regression Tasks

Mean Squared Error (MSE): \[\mathcal{L}(\theta) = \frac{1}{2m} \sum_{i=1}^m \|\mathbf{y}_i - \hat{\mathbf{y}}_i\|^2\]

Equivalent to MLE under Gaussian noise: \(y = f_\theta(\mathbf{x}) + \epsilon\), where \(\epsilon \sim \mathcal{N}(0, \sigma^2)\).

Mean Absolute Error (MAE): \[\mathcal{L}(\theta) = \frac{1}{m} \sum_{i=1}^m |\mathbf{y}_i - \hat{\mathbf{y}}_i|\]

More robust to outliers than MSE (Laplace likelihood).

Huber Loss (smooth combination): \[\mathcal{L}_\delta(y, \hat{y}) = \begin{cases} \frac{1}{2}(y - \hat{y})^2 & \text{if } |y - \hat{y}| \leq \delta \\ \delta |y - \hat{y}| - \frac{1}{2}\delta^2 & \text{otherwise} \end{cases}\]

Quadratic for small errors (smooth gradients), linear for large errors (outlier robustness).

1.5 Backpropagation

Fundamental Principle: Backpropagation efficiently computes gradients of the loss with respect to all parameters using the chain rule of calculus.

1.5.1 Chain Rule Foundation

For composed functions \(z = f(y)\) and \(y = g(x)\):

\[\frac{\partial z}{\partial x} = \frac{\partial z}{\partial y} \cdot \frac{\partial y}{\partial x}\]

In neural networks, each layer is a function \(\mathbf{z}^{[\ell+1]} = f^{[\ell]}(\mathbf{z}^{[\ell]}, \mathbf{W}^{[\ell]}, \mathbf{b}^{[\ell]})\).

Forward Pass: Compute activations sequentially:

\[\mathbf{z}^{[0]} = \mathbf{x}\] \[\mathbf{z}^{[\ell+1]} = \sigma^{[\ell]}(\mathbf{W}^{[\ell]} \mathbf{z}^{[\ell]} + \mathbf{b}^{[\ell]})\] \[\hat{y} = \mathbf{z}^{[L]}\]

Backward Pass: Compute gradients recursively from output to input.

1.5.2 Gradient Computation

Define the error signal at layer \(\ell\): \[\boldsymbol{\delta}^{[\ell]} = \frac{\partial \mathcal{L}}{\partial \mathbf{z}^{[\ell]}}\]

Recursive Formula (chain rule): \[\boldsymbol{\delta}^{[\ell]} = \left(\mathbf{W}^{[\ell]}\right)^\top \boldsymbol{\delta}^{[\ell+1]} \odot \sigma'(\mathbf{z}^{[\ell]})\]

where \(\odot\) is element-wise multiplication and \(\sigma'\) is the derivative of the activation.

Parameter Gradients:

\[\frac{\partial \mathcal{L}}{\partial \mathbf{W}^{[\ell]}} = \boldsymbol{\delta}^{[\ell+1]} \left(\mathbf{z}^{[\ell]}\right)^\top\] \[\frac{\partial \mathcal{L}}{\partial \mathbf{b}^{[\ell]}} = \boldsymbol{\delta}^{[\ell+1]}\]

1.5.3 Computational Efficiency

Why Backpropagation?

  • Naively computing \(\nabla_\theta \mathcal{L}\) using finite differences requires \(O(|\theta|)\) forward passes
  • Backpropagation computes all gradients in one forward + one backward pass
  • Time complexity: \(O(W)\) where \(W\) is the number of edges in the computational graph

Memory Optimization:

  • Storing all intermediate activations for backward pass requires \(O(L \cdot d)\) memory
  • Gradient checkpointing trades computation for memory: recompute activations during backward pass

Interview Insight: Modern frameworks (PyTorch, JAX) use automatic differentiation (autograd) which generalizes backpropagation to arbitrary computation graphs. Understanding the chain rule is essential for debugging gradient flow issues.

1.6 Optimization Algorithms

1.6.1 Gradient Descent Variants

Core Update Rule: \[\theta_{t+1} = \theta_t - \alpha \nabla_\theta \mathcal{L}(\theta_t)\]

where \(\alpha > 0\) is the learning rate.

Three Flavors:

  1. Batch Gradient Descent: Compute loss over entire dataset

    • Accurate gradient estimates
    • Slow and memory-intensive for large datasets

  2. Stochastic Gradient Descent (SGD): Use one sample at a time

    • Fast updates
    • High variance in gradient estimates
    • Can escape shallow local minima (noise helps exploration)

  3. Mini-Batch Gradient Descent: Use batch of \(B\) samples (typically \(B \in [32, 512]\))

    • Standard choice in practice
    • Balances gradient accuracy and computational efficiency
    • Batch size affects generalization (smaller often better)

Why Mini-Batches Work:

  • Vectorized operations on GPUs/TPUs are efficient
  • Stochasticity helps escape sharp minima (which generalize poorly)
  • Effective batch size can be increased via gradient accumulation

1.6.2 Momentum-Based Methods

SGD with Momentum: \[\mathbf{v}_{t+1} = \beta \mathbf{v}_t + (1-\beta) \nabla_\theta \mathcal{L}(\theta_t)\] \[\theta_{t+1} = \theta_t - \alpha \mathbf{v}_{t+1}\]

where \(\beta \in [0, 1)\) is the momentum coefficient (typically \(\beta = 0.9\)).

Intuition: - Gradient is a noisy estimate of the true descent direction - Momentum accumulates an exponentially weighted moving average - Acts like a “heavy ball” rolling downhill—builds velocity in consistent directions, dampens oscillations

Benefits:

  • Accelerates convergence in directions of low curvature
  • Reduces oscillations in directions of high curvature
  • Can pass through small barriers in loss landscape

Physical Analogy: Consider optimizing on a ravine:

  • Pure SGD oscillates across narrow dimension
  • Momentum dampens oscillations while accelerating along the ravine

1.6.3 Adaptive Learning Rates

Motivation: The loss landscape is often ill-conditioned—curvature varies dramatically across parameter dimensions. A single global learning rate is inefficient:

  • Too large → oscillates in steep directions
  • Too small → slow progress in flat directions

Ideal Solution: Newton’s Method uses the Hessian \(\mathbf{H}\) (second derivatives): \[\theta_{t+1} = \theta_t - \alpha \mathbf{H}^{-1} \nabla_\theta \mathcal{L}\]

This normalizes by curvature, but computing/inverting \(\mathbf{H}\) is prohibitively expensive for high-dimensional \(\theta\).

Practical Approach: Approximate the diagonal of the inverse Hessian using gradient statistics.

1.6.3.1 RMSProp

Algorithm: \[\mathbf{v}_t = \beta \mathbf{v}_{t-1} + (1-\beta) \nabla_\theta \mathcal{L}(\theta_t)^2\] \[\theta_{t+1} = \theta_t - \frac{\alpha}{\sqrt{\mathbf{v}_t + \epsilon}} \odot \nabla_\theta \mathcal{L}(\theta_t)\]

where:

  • \(\mathbf{v}_t\) is the moving average of squared gradients (element-wise)
  • \(\epsilon \approx 10^{-8}\) prevents division by zero
  • \(\beta \approx 0.9\) is the decay rate

Intuition:

  • Parameters with consistently large gradients get smaller effective learning rates
  • Parameters with small gradients get larger effective learning rates
  • Approximates diagonal Hessian via \(\mathbb{E}[g^2] \approx \text{diag}(\mathbf{H})\) when loss is quadratic

1.6.3.2 Adam (Adaptive Moment Estimation)

Algorithm: Combines momentum (first moment) and RMSProp (second moment):

\[\mathbf{m}_t = \beta_1 \mathbf{m}_{t-1} + (1-\beta_1) \nabla_\theta \mathcal{L}(\theta_t)\] \[\mathbf{v}_t = \beta_2 \mathbf{v}_{t-1} + (1-\beta_2) \nabla_\theta \mathcal{L}(\theta_t)^2\]

Bias Correction (important for early iterations): \[\hat{\mathbf{m}}_t = \frac{\mathbf{m}_t}{1 - \beta_1^t}, \quad \hat{\mathbf{v}}_t = \frac{\mathbf{v}_t}{1 - \beta_2^t}\]

Update: \[\theta_{t+1} = \theta_t - \frac{\alpha}{\sqrt{\hat{\mathbf{v}}_t} + \epsilon} \odot \hat{\mathbf{m}}_t\]

Hyperparameters (standard defaults):

  • \(\beta_1 = 0.9\) (momentum)
  • \(\beta_2 = 0.999\) (RMSProp decay)
  • \(\alpha = 0.001\) (learning rate)
  • \(\epsilon = 10^{-8}\)

Why Bias Correction?

  • \(\mathbf{m}_0 = \mathbf{v}_0 = \mathbf{0}\) → biased toward zero initially
  • Correction factors \((1-\beta^t)^{-1}\) compensate for this initialization bias
  • Becomes negligible for large \(t\)

Adam vs. SGD Trade-off:

  • Adam: Faster initial convergence, less sensitive to learning rate
  • SGD+Momentum: Often better final generalization (especially in vision)
  • Current research: AdamW (Adam with decoupled weight decay) bridges this gap

Interview Question: “When would you choose Adam over SGD?” Answer: Adam for fast prototyping, non-stationary problems, and when tuning learning rate is difficult. SGD+momentum when generalization is critical and you have time for hyperparameter search. Transformers typically use Adam/AdamW.

1.6.4 Learning Rate Schedules

Motivation: Fixed learning rates are suboptimal: - Early training: Large LR for fast progress - Late training: Small LR for fine-tuning

Common Schedules:

  1. Step Decay: \[\alpha_t = \alpha_0 \cdot \gamma^{\lfloor t/s \rfloor}\] Drop LR by factor \(\gamma\) every \(s\) epochs (e.g., \(\gamma=0.1\), \(s=30\))

  2. Exponential Decay: \[\alpha_t = \alpha_0 \cdot e^{-\lambda t}\]

  3. Cosine Annealing: \[\alpha_t = \alpha_{\min} + \frac{1}{2}(\alpha_{\max} - \alpha_{\min})(1 + \cos(\pi t/T))\] Smooth decay to \(\alpha_{\min}\) over \(T\) iterations

  4. Warmup: \[\alpha_t = \alpha_{\text{max}} \cdot \min\left(1, \frac{t}{T_{\text{warmup}}}\right)\] Linear increase for first \(T_{\text{warmup}}\) steps

    Why? Large initial learning rates can destabilize training when parameters are random. Warmup is especially important for Transformers.

  5. One-Cycle:

    • Increase LR from \(\alpha_{\text{min}}\) to \(\alpha_{\text{max}}\) (30% of training)
    • Decrease LR back to \(\alpha_{\text{min}}\) (70% of training)
    • Popular for fast convergence in limited-budget scenarios

Practical Advice:

  • ResNets: Step decay at epochs 30, 60, 90
  • Transformers: Warmup + cosine or inverse square root decay
  • Try adaptive schedules (ReduceLROnPlateau) when validation loss plateaus

1.7 Generalization and Regularization

1.7.1 Train/Validation/Test Split

Standard Practice:

  • Training set (70-80%): Optimize model parameters \(\theta\)
  • Validation set (10-15%): Select hyperparameters, early stopping
  • Test set (10-15%): Report final performance (use only once!)

Why Three Splits?

  • Validation performance guides model selection → introduces bias
  • Test set remains untouched until final evaluation → unbiased performance estimate

Cross-Validation: When data is limited, use \(k\)-fold CV on train+validation, reserve test set for final evaluation only.

  1. “Walk me through backpropagation for a 2-layer network.”

  • Understand trade-offs: No single best optimizer/regularizer—depends on problem
